# Milestone 2: Opinionated Static Analysis Linter Engine & Rules

**Milestone Goal:** Implement the `code-review opinionated` tool with `syn` AST traversal, implementing rules for inline modules, dummy unit structs, VCS path resolution, raw string errors, clippy suppression hygiene, test naming/assertion conventions, and redundant conversions. Integrate the engine into the CLI with unified diagnostic reporting and exit codes.

## Detailed Acceptance Criteria

### Acceptance Criteria for M2-T0:
1. `crates/opinionated/SPEC.md` exists and defines:
   - Purpose and 6 mandatory invariants for opinionated static analysis.
   - Specific AST patterns, false-positive mitigations, and diagnostic messages for all 7 rules.
   - Public API types, traits, and error taxonomy.
   - Test verification strategy.
2. `plan/M2.md` exists with task checklist and acceptance criteria.
3. `plan/FEEDBACK_M2.md` exists with human review template.
4. `PLAN.md` is updated to mark M2-T0 completed.

### Acceptance Criteria for M2-T1:
1. `syn` 2.0 with `["full", "visit", "extra-traits"]` and `quote` 1.0 are configured in `Cargo.toml`.
2. `engine.rs` can scan a directory or single file, ignoring `.git`, `.jj`, `target`, and hidden directories.
3. Files with syntax errors produce structured diagnostics without crashing the engine.
4. `LintContext` accurately provides source lines and translates AST spans to `code_review_diagnostics::Span`.
5. All visitor engine unit tests pass under `cargo test`.

### Acceptance Criteria for M2-T2:
1. `no_inline_mods` flags `mod foo { ... }` in `main.rs` and `lib.rs` while ignoring `#[cfg(test)] mod tests { ... }`.
2. `free_functions` flags unit structs whose associated functions take no `self` parameters and implement no traits.
3. `path_resolution` flags relative paths in `Path::new`, `File::open`, and `fs::read/write` calls not anchored to `CARGO_MANIFEST_DIR`.
4. `error_types` flags `Result<T, String>` and `Result<T, &str>` in non-test function signatures.
5. `clippy_suppress` flags `#[expect(...)]` or `#[allow(...)]` lacking `reason = "..."` or lacking an explanatory comment on the preceding line.
6. `test_patterns` flags non-compliant test names, `assert_eq!` macro usage in test functions, and `.unwrap()` calls in test bodies.
7. `no_redundant_conversions` flags redundant `serde_json::to_string` followed by `serde_json::from_str`.
8. Positive and negative test cases verify each rule.

### Acceptance Criteria for M2-T3:
1. `opinionated` binary and `code-review opinionated` subcommand parse `--path`, `--format`, `--quiet`, and `--fix`.
2. Clean run on healthy codebase yields exit code 0.
3. Detection of errors yields exit code 1 and outputs formatted report (console, json, or markdown).
4. Invalid path or unparseable argument yields exit code 2 with descriptive error on stderr.
5. Integration tests pass under `cargo test`.

### Acceptance Criteria for M2-T4:
1. All unit and integration tests pass across the workspace (`cargo test`).
2. Clippy is completely clean with zero warnings (`cargo clippy`).
3. Code formatting conforms to rustfmt (`cargo fmt --check`).
4. `plan/M2.md` and `PLAN.md` reflect Milestone 2 completion.
