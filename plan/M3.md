# Milestone 3: Linter & Formatter Runner Aggregator (`code-review check`)

**Milestone Goal:** Implement `code-review check` to run `cargo fmt --check`, `cargo clippy --message-format=json`, `code-review purist`, `cargo audit --json`, and checks/formatters for markdown, toml, and json files if available, normalizing findings into a unified `DiagnosticReport`. Add Jujutsu changed-file filtering (`--changed-only`), threshold enforcement (`--fail-on`), and multi-format reporting.

## Detailed Acceptance Criteria

### Acceptance Criteria for M3-T0:

1. `crates/check/SPEC.md` exists and defines:
   - Tool runners (`cargo fmt`, `cargo clippy`, `code-review purist`, `cargo audit`, markdown, toml, json).
   - JSON parsing specifications for rustc/clippy and cargo audit.
   - Jujutsu `--changed-only` filtering logic.
   - CLI options and exit code taxonomy.
2. `plan/M3.md` exists with task checklist and acceptance criteria.
3. `plan/FEEDBACK_M3.md` exists with human review template.
4. `PLAN.md` is updated to reflect M3-T0 completion.

### Acceptance Criteria for M3-T1:

1. `FmtRunner` runs `cargo fmt --all --check` and converts diffs into `Diagnostic` findings with rule `fmt::formatting`.
2. `ClippyRunner` streams `cargo clippy --message-format=json`, correctly parsing rule codes, severity levels, primary source spans, and suggestions.
3. `AuditRunner` executes `cargo audit --json` with graceful `--no-fetch` fallback and maps advisories to `Diagnostic` items.
4. `PuristRunner` collects AST diagnostic findings.
5. All parsers are unit tested with `googletest`.

### Acceptance Criteria for M3-T2:

1. `JjVcs` runs `jj --no-pager diff --summary` and extracts modified and added file paths.
2. Filter logic removes diagnostics for untouched files while preserving global diagnostics or modified file findings.
3. Graceful error handling when target is not a Jujutsu repository.
4. Unit tests verify parsing of various diff status lines.

### Acceptance Criteria for M3-T3:

1. `CheckCommand` parses all options: `--path`, `--format`, `--fail-on`, `--changed-only`, `--quiet`, `--skip-*`.
2. Renders reports via `code_review_diagnostics::render_report` in console, json, or markdown format.
3. Exits with 0 when clean, 1 when violations exceed `--fail-on` threshold, and 2 on operational failure.
4. Wired into `code-review` binary and CLI tests pass.

### Acceptance Criteria for M3-T4:

1. Workspace passes all tests (`cargo test --all-targets --all-features`).
2. Zero Clippy warnings (`cargo clippy --all-targets --all-features -- -D warnings`).
3. Rustfmt is cleanly formatted (`cargo fmt --check`).
4. Purist AST linter reports zero violations (`cargo run -p code-review -- purist --path .`).
5. Markdown, TOML, and JSON checkers/formatters run if available on system.
6. `plan/M3.md` and `PLAN.md` reflect Milestone 3 completion.
